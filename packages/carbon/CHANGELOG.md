# Changelog

## 0.3.0

### 既定の cwd が spar の `root()`（`CLAUDE_PROJECT_DIR`、無ければ cwd）になった

控えの置き場がシェルの現在地に引きずられなくなった。経緯は spar の CHANGELOG。

## 0.2.0

### `@hyuga/spar@^0.2.0` を要求するようになった

`runDirectly` と `readStdin` が `@hyuga/spar/cli` に移った。この副経路は spar 0.2.0 で入ったもので、
公開済みの 0.1.0 には無い。下限を上げずに公開すると、控えを取るはずのフックが
`ERR_PACKAGE_PATH_NOT_EXPORTED` で沈黙する——**しかも carbon は設計上何も言わない**ので、
気づくのは下書きを取り戻したくなった日になる。

### CLI を実際に起動するテストを12本

黙って動く部品ほど、実際に起動して確かめないと壊れているか分からない。とくに固定したのは
`carbon show` がバイトを返すこと。0.1.1 で直した「一覧には出るのに復元できない控え」の回帰テストで、
PNG を1バイトも変えずに往復することを確かめている。

秘密を控えないこと・リポジトリの外のファイルを控えないこと・ディレクトリやまだ存在しないファイルを
控えないことも、コマンド越しに確かめるようにした。

## 0.1.1

### 控えがバイナリを壊していた

`readFileSync(path, 'utf8')` で読んで書き戻していたので、UTF-8 として読めないバイトが全部
U+FFFD に置き換わっていた。png・pdf・sqlite——テキストでない下書きは、**控えが取られたことに
なっているのに復元できない**。控えを取る部品としては一番痛い壊れ方で、しかも `carbon list` には
ちゃんと出るので、必要になるまで気づけない。

バイト列のまま読み書きするようにした。`carbon show` も同じで、`carbon show <id> > x.png` が
元のファイルに戻る。

## 0.1.0

最初の公開。

発散しているときの下書きは、まだ git に入っていない。エージェントがそこへ上書きすると、
**消えたことにすら気づけない**。収束中の検証ゲートは、この事故を1件も防がない。

carbon（控え）は、上書きの直前にそこにあったものを控える。条件は3つ——巡航形態のときだけ・
git が追っていないファイルだけ・秘密情報は絶対に控えない。そして**一切喋らない**。
下書きに割り込むことは、巡航形態が存在する理由そのものを壊すため。
