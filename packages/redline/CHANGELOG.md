# Changelog

## 0.1.0

最初の公開。

1回ごとの許可確認は、10回目には意味を失う。押している側は「さっきと同じやつ」としか思わないので、
**危険なのは1回の呼び出しではなく、1セッションで積み上がった量**の方だという事実が見えない。

redline（際）は呼び出しではなく出撃を数える。本番への書き込み・不可逆な操作・依存の追加を種類ごとに
加算し、上限に達したら告げる。人が座っているセッションでは**止めずに具申する**——飛ばしているのは
パイロットで、際を越えるかどうかはその人の判断だから。止めるのは `AIRFRAME_AUTONOMY` が立っている
とき、つまり誰も座っていないときだけ。

### 引用は課金しない

このリミッタは、他人に何かを払わせる前に自分の信用を落とした。`npm publish` という文字列を
**検索しただけ**のセッションが、上限3に対して20点まで上がった。中身は README の grep と
workflow ファイルの閲覧で、課金された全部が引用だった。

原因は、コマンドを1つの文字列として正規表現に当てていたこと。コマンドは1つの動作ではない
——`grep "npm publish" README.md && npm publish` はその語を2回含み、publish は1回しかしない。
文字列全体に当てれば両方に課金され、どちらが本物だったかは後から誰にも分からない。

コマンドを実際に走るものへ切り分けてから当てるようにした。区切りはクォートの外の `;` `|`
`&&` `||` と改行で、**印字するだけの動詞**（grep / rg / cat / head / echo / ls / Select-String 等）
で始まる区間は落とす。ヒアドキュメントの本体も落とす——書かれているファイルの中身であって、
実行される行ではないから。`find` `sed` `awk` `xargs` は落とさない。いずれも引数がそれ自体
コマンドなので、その引数は「ただの文字列」ではない。

本番パスの判定も同じ扱いにした。`grep -r X:/01-client/ notes/` は本番の名前を口にするだけで、
本番に届いてはいない。

数字が雑音で埋まると雑音として読まれ、そのとき止めるべき1件が、止めなくてよかった20件と
同じ顔で流れていく。
